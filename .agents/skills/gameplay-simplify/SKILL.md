# 玩法操作简化规范

总纲：工作区 `docs/feature-design/qq-interaction/玩法操作简化总纲_20261119.md`。
首批样例：同目录 `玩法操作简化三件套设计_20261119.md`。
本文件是**硬性条款**，与总纲冲突时以总纲为准并回报差异。

## 什么时候用

- 新增一个玩法、新增一条指令、新增一个交互入口
- 改造既有玩法的前置条件、拒绝分支、错误提示
- 代码里出现 `请先…`、`缺少…`、`不足` 这类前置阻塞文案
- 设计评审时判断一个交互是否"够简化"

## 一句话原则

**能免费撤回的，自动做；要花软币的，问一次带总价；改了不能撤的，先预览再确认；改不动的，说清楚给跳转。**

玩家发一条核心指令就该能玩。不要让他先发现前置、再找入口、再回来。

## 四类前置，必须归类

任何前置缺口都要先归到下面一类，再决定交互。**不归类就写拒绝文案，视为未完成设计。**

| 类型     | 判定                                     | 交互必须是什么                             |
| -------- | ---------------------------------------- | ------------------------------------------ |
| 配置型   | 玩家不缺资源，只是没做个与意图无关的选择 | 自动补齐并继续；回执写明怎么切回           |
| 消耗品型 | 真缺物资，可用软币买                     | 同气泡报精确缺口 + 报价 + 「购买并继续」   |
| 不可逆型 | 执行后改变玩家状态且不好撤               | 先预览（改什么/花什么/能否撤），确认后继续 |
| 硬门槛型 | 境界、时段、他人审批、付费货币           | 不简化，说清当前状态+还差什么+达成路径     |

## 十条硬性要求

1. **一步之差。** 缺前置时，玩家总点击次数 ≤ 核心动作 1 次 + 确认 1 次。
2. **机器人不算不改判。** 缺口类型、数量、价格一律由服务端给出。机器人只排版，不推断前置、不算价、不自己判断"缺不缺"。
3. **同事务。** 补齐前置与执行原动作必须在一个事务里提交，禁止拆成两次网络请求，避免"买了没开成"。
4. **精确数值。** 报 `需要 15，现有 1，还缺 14`，不报"不足"。多原因要拆开说，不挤成一句。
5. **一次一个缺口。** 多个缺口按依赖顺序逐个解决，不并列堆给玩家。
6. **不代选长期方向。** 道途、多候选天工、多候选 Buff 这类有长期影响或平级平权的选择，一律不静默代选；给预选+一键继续，或给对比页。
7. **付费货币红线。** 灵晶、道晶、仙玉、人民币**永远不出现"一键买"按钮**，只给跳转入口。软币（灵石、灵鳞钱）才可以一键买。
8. **可退出。** 任何缺口气泡都要有返回入口；退出不扣任何资源。
9. **口径一致。** 同一缺口在指令、按钮、通知三个入口看到的数字必须相同。
10. **80 字符。** 所有按钮指令含凭据不超过 80 个 Unicode 字符，用 `[...command].length` 判定，禁止截断或补齐。

## 气泡骨架

统一用这套形状，玩家在任何玩法看到的缺口提示都长一样：

```
【标题】玩法 · 需要先准备
┌────────────────────────────┐
│ 状态：缺少 <配置名/物品名>     │  ← 第一行必须说清缺什么
│ 原因：<一句话为什么挡住>        │
│ 需要：<数量> / 现有：<数量>     │  ← 消耗品型才有
│ 费用：<金额><币种>             │  ← 涉及扣费才有
└────────────────────────────┘
[购买并继续] [换个方式]          ← ≤3 个动作
[返回<玩法主页>]                 ← 页脚永远保留
```

同时必须遵守 [bubble-style](../bubble-style/SKILL.md)：状态行带事实标签、对象行 `**名称** #ID`、返回放页脚、分页用 `nav`、符号只用规定集合。

## 新增玩法时必须做的

1. 先写清这个玩法的四类前置分别是什么（哪一类、缺时给什么交互）。
2. 核心动作指令**直接可用**，不要让玩家先跑别的指令配置。
3. 每个前置分支都必须有交互，不能只有一句拒绝文案。
4. 数值、境界、时段等门槛本身**照旧保留**，简化只减步骤不减门槛。

## 自检清单（提交前逐项打勾，并在交付说明里写结论）

- [ ] 每个前置缺口都已归类到四类之一
- [ ] 缺前置时总点击 ≤ 2 次
- [ ] 缺口数字精确（需要/现有/还差），没有"不足"这类模糊词
- [ ] 补齐与原动作同事务；重试原引用返回原回执，不重复扣
- [ ] 没有静默代选长期方向或平级候选
- [ ] 没有出现灵晶/道晶/仙玉/人民币的一键购买按钮
- [ ] 每个缺口气泡都有返回入口，退出不扣资源
- [ ] 同一缺口在指令/按钮/通知三处数字一致
- [ ] 所有按钮指令 ≤ 80 Unicode 字符，测试覆盖最大合法参数与越界拒绝
- [ ] 门槛数值一行未改；既有入口与按钮一个未删（零阉割）
- [ ] 气泡符合 bubble-style，且已出「改前/改后」对照并经二次确认

任一项打不了勾，就回到总纲和目标代码继续核对，不要先实现后解释。

## 明确禁止

- 新增"钓鱼"这类未登记别名（垂钓准入只认垂钓／渔获／钓具／渔市）
- 把确认机制从 `r1_` 引用改成紧凑载荷
- 顺手放宽境界、星数、职业等级等门槛
- 顺手修复本任务范围外的玩法
