# 灵墟洞天最简 MVP：QQ 交互契约

这是额外最简版的 QQ 展示入口，不替代完整设计。只负责真实服务端页面的展示与操作转交，不在机器人中生成奖励、模拟战斗或缓存权威确认。

主页、简介、玩法和阵法师剧情的当前样式见 [洞天页面验收](bubble-style/BATCH-20261112-LINGXU-PLAY-GUIDE.md)。地图和出口见 [洞天地图验收](bubble-style/BATCH-20261111-LINGXU-MAP.md)，九品阵法师样式见 [阵法师验收](bubble-style/BATCH-20261111-LINGXU-FORMATION-GRADES.md)。

- 主系统入口：`/灵墟洞天`；副职业入口：`/阵法师`。两者都请求现有业务通道的 `lingxu.command`，`arguments={}`，原完整指令随 `messageText` 传递。
- QQ 群聊和私聊均可查看状态、入场、设置倾向、看地图、管理墟行囊、翻阅行记和使用阵法师。页面回复到发起指令的会话，操作与确认均绑定发起角色。
- 所有主页状态共用「简介」「玩法」「阵法师」「行记」四个顶部入口和「状态、行动、命数、行囊、阵盘」五行。地图、倾向、打开和查看入口各自位于对应行右侧；生效中的阵盘在该行展示剩余时长。
- 入场确认和暂不能入场使用同样的五行与行内入口。入场条件、消耗和风险放在同一个引用块下方，确认与取消各占一行。命数为零时显示恢复时间和返回入口。洞天行记、推送和阵盘说明也统一使用「命数」。
- 入场后按实际状态显示轮次和休息提示。轮次单独分段；只有服务端确认行踪暴露时才分段加粗显示「行踪已暴露」。探索中页脚的「返程」和「休息」各占一行，恢复命数后自动继续。未入场时页脚为「准备入场」和「提取回执」。
- 「简介」展示设计原稿的三段故事，使用阵盘与二十四道残存星轨建立联系。「玩法」按第一次入场的操作顺序介绍倾向、跑图、命数、行囊保护、安全返程、行记和阵盘，并提供实际入口。旧 `/灵墟洞天 入门` 只保留为兼容指令。
- 「行动倾向」集中设置行动强度、对人、对怪和自动返程。
- 地图顶部选择外围、内围或核心，默认外围。三组各一页，分别展示8、8、1处地域，外围属阳，内围属阴。入场后可从地图名右侧选择前往，下方显示该地的产出与出口。指定出口撤离可从页脚的「选择出口」进入，出口列表展示各方位的撤离条件。
- 行囊每页两物品，物品右侧提供保护和丢弃按键，使用该物品显示的数字编号。丢弃按键填入默认丢弃1件的指令，末尾可加数量。发送后先看销毁确认；确认后的物品永久销毁，不落到地图、不转给其他玩家。行囊内部提供扩容入口。
- 行记显示当前或最近一局的最新120条，每页3条。单条记录使用一个引用块，以加粗时间为标题，后接固定的数字编号。底部的「详情」填入 `/灵墟洞天 记录 <编号>`。新增记录和翻页不会改变旧记录的编号。
- 行动详情展示实际扣费、战况与损失。只有确实掉落时才显示失物去向，败给玩家时由胜者获得，败给异种时计入该异种的下一次掉落。货币损失按实扣金额列出。
- 行记页底部可选择将洞天推送发到私聊、本群或关闭。选择本群需从目标群操作。常规每30分钟汇总，战败或撤离即时发送。
- 实际推送由已启用的 QQBot 通知流投递。`yarn dev --login qq-bot` 可测试指令与设置，默认不启动主动通知流。
- 底栏为原 `我｜战｜本｜动｜店`。蓝色指令链接仅填入输入框，发送由玩家决定；不使用不受支持的 `qqbot-cmd-enter show`。
- 普通指令使用玩家可见的地域、界门、阵盘路线或数字编号。只有需要绑定原预览的确认按键使用服务器 `r1_UID_lx_时间_随机数` 引用，完整指令包含前缀最多80个 Unicode 字符。确认失败保留原引用和原业务操作。

## 页面数据

```ts
type LingxuPage = {
  title: string; // 灵墟洞天 / 阵法师，或 “主题 · 页面”
  privateOnly: boolean; // 新版页面发 false
  tabs?: Array<{ label: string; command: string }>; // 地图顶部的三个分区
  sections: Array<{
    title?: string;
    id?: string;
    lines: string[];
    experience?: string[];
    harvest?: string[];
    actions?: Array<{ label: string; command: string }>;
  }>;
  actions?: Array<{ label: string; command: string }>;
  nav?: { page: number; totalPages: number; total?: number; command: string };
};
```

QQ 渲染从当前事件取得群聊或私聊上下文。服务端保留 `privateOnly` 字段以兼容旧页面结构。

可选数组应省略或传 `[]`，不传 `null`。对象至多3键，普通页的页末至多8键分两行，含翻页至多10键，另有5格原底栏。洞天主页允许4个顶部入口、4个行内入口和2个页脚按钮。地图每页最多3个分区标签、8个前往键和2个页脚键。服务器事实文案原样展示；不完整页面拒绝展示，不补造本地默认状态。

## 阵法师九品成长与12小时阵效

未入门时，`/阵法师` 展示守阵人接引星轨的剧情。玩家主动免费入门后，回执引导查看图谱、按路线备料制作及激活。已入门玩家直接查看职业面板。

职业复用原副职业记录，无品至九品，经验达到条件自动晋级。职业品阶限制制作和升品；已购高品成品按服务器规则激活，不在QQ另加职业品阶限制。三条路线均为无品基础属性，随后一至九品各一项特色效果，三品、六品、九品为大节点；全部效果来自服务器统一配置。

制作固定一件无品成品，消耗少量洞天材料与10灵晶，基础职业经验10；升品只耗四类洞天材料，每步升至g品的基础经验为10×g。一键升品只固定预览时职业上限及材料允许的目标，不因本次经验触发晋级而继续追加；例如无品升至三品的基础经验合计10+20+30=60。实际经验增益与结算由原职业经验提供者处理，回执展示原成功结果。

职业页显示品阶、经验、下阶需求、可升级上限、当前生效阵盘、剩余时长与截止。我的阵盘每页两件，每件提供“升一品”“一键升品”“激活12小时”，达到上限时显示原因，不提供无效升品键。

激活消耗所选真实成品，确认成功后立即生效12小时；同路线刷新为确认时刻后12小时，不累加剩余时长；不同路线覆盖，不返还成品。终止阵效同样先预览确认，剩余时长与已消耗资源不返还。旧「装备」「卸下」只作为激活和终止的预览入口，不直接消费或终止。

各个未冻结的洞天行动读取全局当前有效阵效，已冻结行动保持原快照。激活、覆盖、终止、到期不会倒改已经冻结的行动，也不会通过入场延长12小时时限。行囊容量仍按本局入场快照，和阵效时限分开处理。

制作、升品、激活及终止统一使用服务端Redis `r1...lx...` 原预览引用，缓存包含原品阶、职业状态、实例版本、固定逐级材料及原阵效编号/截止。确认只提交原目标与原操作，不重建最新参数；失败后保留原引用供核对与重试。

## 运行范围

新增入口仍经原机器人身份、中间件与真实 HTTP 通道。服务端须配套注册 `lingxu.command`，并将“灵墟洞天”“阵法师”加入天书功能目录及展示准入；否则生产发送过滤器会隐藏未知指令。未配套时只显示固定失败提示，不伪装成可玩版本。

离线框架测试证明处理器、格式节点、HTTP 契约和发送回执；不等同于 QQ 实机投递、远程数据库结算、部署或十万人压力测试。
