# 数值气泡与 JS 整数精度审计（2026-10-31）

本轮检查 `src/api/core`、`src/api/bot`、`src/api/schemas`、`src/response`、`src/response-apps`、`src/utils` 中 JSON 解析、安全整数校验、显式 Number 转换、千分位与中文单位展示。扫描命中只是候选，不能等同于所有生产数据或 QQ 实机验证。

## 已落地

- HTTP JSON 接收在原始数字 token 尚可读取时保留大整数，安全整数仍用 number，超限整数使用 bigint；支持整数科学记数法。非有限值、无法无损表示的大数小数明确拒绝。
- 发出的 JSON 请求拒绝已经超出安全整数范围的 number，不通过 Number(bigint) 绕过参数校验。
- 中文数值统一支持万、亿、万亿、亿亿，最多两位小数，单位边界进位，负值保留符号；整数使用 bigint 运算，不先舍入为浮点数。
- 稻草人保留精确伤害文本兼容，并可接收公共解析层产生的 bigint。
- 凶兽资料、排行榜、单次/批量挑战、生命/伤害/治疗统计、奖励预览和领奖条目接通精确数值；领奖合计使用 bigint 复核，不丢失一单位差异。
- 境界/区境界排行修为、战力/区战力排行、丹师排行经验与累计次数、战力成就当前值/目标/差额使用中文单位；相关展示指标接受大整数，身份与分页仍单独校验。
- 万宝楼/道侣商店、玩家商店、转盘共用资产卡接通精确余额；明确货币文本中的数量进行中文单位换算，不转换人民币金额与指令。
- 宗门商店数量、贡献余额和价格不再用 Number 强制转换；队伍战斗明细的奖励展示不再强制转为 Number。

## 验证边界

定向测试覆盖原始 HTTP JSON、MAX_SAFE_INTEGER 两侧、Go int64/uint64 极值、科学记数法、负值、单位进位、混合大小整数合计及一单位差异、凶兽/稻草人/宗门商店实际处理器发送节点和按钮命令。

公共解析层保留精度，不等于任意业务字段都自动获得无限整数范围。未迁移的业务校验仍可能明确拒绝 bigint；不应以放宽所有 ID、次数、页码或支付参数校验代替按字段适配。已在服务端浮点计算或预先舍入的精度无法由机器人恢复。

稻草人标准靶已按用户确认的方案改为读取挑战者当前境界基础生命、防御、速度及境界档案；靶子不行动、不死亡，直接伤害完整计量，DOT 按有限生命基准计算，不再使用整数上限。该标记仅由稻草人服务启用，不改变普通敌人的扣血和死亡规则。源码和离线处理器测试不代表部署或 QQ 实机投递已完成。
