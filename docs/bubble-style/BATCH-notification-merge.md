# 个人通知合并与快捷关闭

普通玩家通知复用现有传输缓冲，固定30秒窗口，每批最多5条，序列化内容累计超过12000字符时拆批；图片等不能安全合并的节点沿用原发送路径。飞信沿用2秒/5条，群欢迎和申请沿用服务端30秒队列。普通消费最多64条在途，其他事件保留在服务端；不增加数据库字段或依赖。

合并键包含平台、机器人、范围、目标和玩家。原文、业务按钮、事件及逐条回执保留，单批失败由原事件重试。缓冲是进程内临时传输状态，重启由持久化事件租约恢复；多实例之间不合批。本次不实现机器人总额度控制，不能保证消除平台限速。

“通知设置”和“我的通知”在整个发送批次末尾单独一行，只出现一次；各条目附当前分类关闭按钮，使用现有 `/通知设置 <category> 关闭`，身份仍由真实指令发送者解析。混合分类消息各自保留关闭按钮。旧通知没有source时归入other；群公共欢迎等仍由群管理控制。关闭后重新认领的通知按现有开关过滤，已经在途的通知可能送出。
