# 引导分支目录分页（2026-11-03）

## 行为

原来新境界目录一次展示全部分支；现在每页6项，原生引导、业务回执后的引导目录以及对话式目录共享同一页码模型。`FormatGui.nav` 的页码与翻页动作计算提取为 `guiNavigation`；对话式将同一 nav 动作转换为无斜杠输入选项。原生按钮显示上一页/下一页，对话式输入保留原分页命令文本。

临时目录只保存展示快照，绑定平台、机器人、玩家与会话，30分钟失效。`/引导目录分页 <目录编号> <页码>` 是新增的只读展示路由，不请求服务端、不推进引导、不领取奖励。每份目录有独立编号，跨境界回看不覆盖旧目录；选择分支仍提交原服务端版本化指令，由服务端核对当前状态。无斜杠分页由插件生命周期直接响应，不需要模型生成新答案。

原生 Context 对分页明确 pass，分页处理器遵守事件启用策略。Markdown 发送失败降级文本时也保留翻页指令。业务反馈原文保留，完整目录不再作为附加回执重复发到分页消息后面。接口输出的完整 branchMenu 不裁剪；分页只发生在展示层。

## 验证

- 真实处理器检查实际 MD.button 与发送回执，首屏6项，下一屏保留原分支命令。
- 无AI：Context放行翻页，不产生业务请求；第二页选择分支仍提交原version和command，并回到小组按钮教学。
- 有AI：实际生命周期返回分页文本，经宿主渲染、成功发送后记录本页选择；连续到第三页仍能选中末项并匹配原插件路由。
- 同一玩家不同境界快照独立；跨用户、机器人、会话不可读取；越界或过期不展示内容。
- 业务回执的目录随附不额外结算；纯文本降级有导航；未做QQ实机验收。

本次未将所有模型生成列表自动分页：改造范围是插件提供的权威教学分支目录。其他玩法长列表继续采用各自已有页面能力，不能把本次验证泛化为所有UI已验收。

本轮验证结果：类型检查与Lint通过；对话游玩回归170通过、10个需要新框架的既有预约用例跳过；原生引导68通过；presentation-primitives 7通过。扩大到全部presentation离线测试为84通过、2失败（锻造页码分隔符、对战剩余次数文案）。在测试装载时替换回HEAD版messageHelper，两个失败仍原样复现，因此不归因于本次导航提取；它们仍是未解决的既有展示测试差异，不能报告为全套通过。
