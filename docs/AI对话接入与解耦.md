# AI 对话游玩接入与解耦

## 本次落地

修仙自己的对话规则已从 AgentLink 迁入 `src/agent-play/`。AgentLink 运行时不再选择修仙 provider、识别修仙动作名、判断注册阶段或保存修仙确认规则。

| 所有者     | 实现与职责                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| ALemonJS   | Expose 动态注册与发现、真实调用方及消息身份、schema、授权、超时和取消                                                                           |
| AgentLink  | 通用 `agent.conversation.v1` 生命周期、AI 模型、通用 Markdown 选择、实际发送与回执、手动消息接管                                                |
| 修仙插件   | `lifecycle.ts` 接入协议；`game-guidance.ts` 注册/教学/普通玩法流程和展示；`game-confirmation.ts` 原操作确认；`guidance-session.ts` 玩家临时会话 |
| 游戏服务端 | 权威账号、进度、库存、收益、操作凭据与幂等结算，保持原实现                                                                                      |

“修仙怎么玩”由宿主发现插件后交给修仙 route/state 判断。玩法介绍是否进入注册、下一步是什么、是否可以消费，都由修仙自己的契约和规则决定。宿主不按名称列出修仙分支。

## 有 AI 的效果

```text
玩家：带我玩修仙
  → 通用宿主询问插件是否接话
  → 修仙读取本人真实状态，提供当前步骤与可选动作
  → AI 用当前名字和口吻说话
  → 宿主生成真实 Markdown 按钮，按钮内容是自然语言
玩家：点击下一项
  → 修仙核对本消息、当前状态与已投递的原选择
  → 原业务 Expose 执行
  → 修仙记录实际回执并组织展示
  → 平台发送成功后，才登记选择已投递
```

以下是表现示意，具体步骤和文字由真实状态决定，不能据此伪造执行结果：

> 大肥鱼：先告诉我你想用的道号，我会按你的选择接着带你。
>
> 玩家：叶飞雨
>
> 大肥鱼：接下来选择角色性别。
>
> [男修] [女修] [退出引导]

`{{guide.name}}` 由修仙插件按通用 `agent.presentation.v1/narrator` 返回值替换。没有 AI 或人格不可用时使用“系统”；宋玉等剧情角色不替换成机器人。

## 无 AI 与手动接管

- 未安装 AgentLink：原修仙指令、注册、剧情、新手引导与分支目录照常使用。
- AI 关闭：已存在的 AI 会话退出并保留业务进度；新请求提示使用 `/踏入仙途` 或 `/我`，不调用模型。
- 玩家随时发送 `/` 原指令：失效旧 AI 回合后放行给原处理器，不等待 AI 完成，也不回滚已提交操作。
- 人格或自动讲解失败：保留原始气泡和按钮，默认自称系统。
- 大量分支继续由修仙原目录和 Markdown input 展示；宿主不硬编码境界和功能数量。

## 故障与确认约束

确认仍绑定玩家、原操作与原预览，未实际投递不能确认。同消息不得借模型自动确认；跨玩家或过期选择拒绝。已消费或已结算事实不能因退出、模型失败、发送失败而撤销，也不能自动换新参数再提交。

原业务返回成功但 `after_call` 失败时，宿主保留原工具回执，停止后续动作并要求核对原结果。临时会话仅为单进程内存状态，不是服务端凭据仓库；重启丢失的选择必须重新读取、核对，不凭最新状态提交旧确认。

## 发布与兼容性

这次同时更新 AgentLink 与修仙机器人包。建议停收消息后配套发布两个包并重启，避免新宿主搭配旧插件时缺少生命周期，或旧宿主同时运行旧适配器。已有游戏存档、原 `/` 命令及服务端确认编号不变；没有数据库或 DB SDK 变更。

原 `agent-link.game-narration.v1` 被通用 `agent.presentation.v1` 取代；新旧版本混用时可选 AI 讲解会降级为系统原气泡，不承诺跨版本继续内存中的 AI 选择。旧气泡的原 `/` 操作仍走原业务校验。

## 验证

- 宿主 `test/plugin-conversation-framework.test.mjs` 和 `test/plugin-routing-framework.test.mjs` 使用独立业务提供插件，证明宿主不依赖修仙动作名。
- 本插件 `yarn test:agent-play`：迁移的确认、注册、玩法接续、状态隔离、回执、故障与手动接管回归；默认使用相邻 AgentLink 已构建的 `lib`。这只是测试依赖，修仙生产源码不导入 AgentLink 文件。
- 本插件框架测试保留原 handler、Hook、Format 与发送回执检查。
- 实际三方集成另用 AgentLink 的 `test/game-guidance-integration.test.mjs`，配合本插件与隔离 Go 夹具；模拟模型不等于真实 AI 或 QQ 实机。
